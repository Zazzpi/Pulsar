# Windows-приложение Pulsar

## Использование

Скачать: [Pulsar.exe](https://github.com/Zazzpi/Pulsar/releases/latest/download/Pulsar.exe).

Один файл для Windows 10/11 x64. Запуск — двойным щелчком, без установки,
Python, Docker, командной строки и прав администратора. Файл можно хранить
в обычной папке пользователя или сделать на него ярлык.

На первом экране доступны:

- **Посмотреть демо без сервера** — демонстрационные клиенты и операции,
  все семь вкладок, наблюдения на 90 дней и заметки. Демонстрационные
  наблюдения и заметки сохраняются локально между запусками.
- **Войти** — работа через общий сервер Pulsar. Нужны его HTTPS-адрес,
  имя пользователя и пароль от администратора. После успешного входа
  приложение запоминает адрес и имя; пароль и токен на диск не записываются.
- **Открыть сохранённые данные** — просмотр ранее полученной информации
  с рабочего сервера при недоступности сети.

DEMO явно обозначен в окне и изолирован от рабочих данных. Он не подключается
к сети, не требует учётной записи и не изменяет WMS. Его остатки и события
являются примерами, а не сведениями из реальной базы.

Данные пользователя хранятся в `%LOCALAPPDATA%\Pulsar`:

```text
cache.db          последние просмотренные данные API
demo.sqlite3      наблюдения и заметки локального DEMO
logs/pulsar.log   журнал с ограничением размера
```

При замене EXE новой версией эти файлы остаются. Чтобы получить свежие
рабочие данные, нужен общий сервер; упаковка desktop в EXE не заменяет его.
Наличие существующей WMS само по себе не гарантирует наличие API Pulsar.

## Для разработчика: воспроизводимая сборка

[Windows executable](../.github/workflows/windows.yml) в GitHub Actions
проверяет desktop-тесты на Windows, собирает `Pulsar.exe`, запускает **сам
собранный EXE** из временной папки вне исходников и проверяет:

- открытие окна авторизации и окна локального DEMO;
- отрисовку сводки DEMO;
- работу SQLite;
- наличие requests внутри пакета и CA-сертификатов HTTPS.

Сборка выполняется на Windows x64 с Python 3.12. Используется
[PyInstaller one-file / windowed](https://pyinstaller.org/en/stable/operating-mode.html):
Python, Qt и зависимости включены в файл, консоль не открывается.
[PyInstaller требует сборку под целевой ОС](https://www.pyinstaller.org/en/stable/),
поэтому Linux-проверка исходников дополняется отдельным Windows runner.

Сборку можно повторить через Actions → Windows executable → Run workflow.
Артефакт `Pulsar-windows-x64` содержит EXE, SHA256, версии зависимостей,
результат проверки и краткую инструкцию. Проверенный EXE публикуется в Releases.

Команда сборки вручную, **только для разработчика на Windows**:

```powershell
python -m pip install -r packaging/requirements.txt
python -m PyInstaller --noconfirm --clean --onefile --windowed --name Pulsar --paths . --noupx --copy-metadata PyQt6 --copy-metadata PyQt6-Qt6 --copy-metadata requests --copy-metadata certifi packaging/windows_entry.py
```

Результат — `dist/Pulsar.exe`. Секреты `.env`, backend, PostgreSQL и локальные
БД в EXE не включаются. Сборка не подписана цифровой подписью организации.
Реальное подключение к серверу заказчика требует предоставленного адреса
и доступа; локальный DEMO позволяет проверить интерфейс без них.
