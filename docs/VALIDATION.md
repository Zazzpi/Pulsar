# Проверка MVP

Проверено локально 18 сентября 2026 года. Все исходные данные WMS в этих
проверках — демонстрационные или специально созданные тестовые данные.
Подключение к production WMS не выполнялось.

## Выполненные проверки

| Проверка | Результат |
| --- | --- |
| Установка Python-зависимостей в `.venv` | Успешно |
| `python backend/manage.py check` | Нет замечаний |
| `python backend/manage.py makemigrations --check --dry-run` | Нет отсутствующих миграций |
| `QT_QPA_PLATFORM=offscreen pytest -q` | 88 тестов пройдено; API, repository, cache и desktop |
| `docker compose config --quiet` | Конфигурация корректна |
| `docker compose up -d --build` | Backend и PostgreSQL запущены, healthchecks успешны |
| Миграции собственной PostgreSQL при старте контейнера | Применены |
| `python scripts/smoke_api.py` | Вход, поиск, страницы, сводка, наблюдение 90 дней, заметки, пять подробных API, отзыв токена |
| `docker compose exec -T backend python < tests/postgres_smoke.py` | Реальные SQL-запросы на отдельной временной PostgreSQL-базе; JOIN, изоляция по клиенту, сторно, пагинация, параметры; UPDATE запрещён |
| `docker compose exec backend python manage.py snapshot_metrics` | Снимки сохранены, ошибок нет |
| `QT_QPA_PLATFORM=offscreen python -m tests.desktop_smoke` | HTTP в рабочем Qt-потоке, callback в GUI-потоке, повторное открытие SQLite, изоляция пользователей, запрет offline-изменений |
| `QT_QPA_PLATFORM=offscreen python -m tests.gui_smoke` | Настоящие окна входа и клиентов, наблюдение, семь вкладок, вторая страница движений, сохранение заметки |
| Остановка backend внутри GUI smoke | Сохранённая сводка остаётся видна; показано предупреждение о неактуальности |
| Повторный запуск окон при остановленном backend | Данные восстановлены из SQLite; изменения отключены |

`tests/gui_smoke.py` временно останавливает **локальный** контейнер backend и
запускает его обратно в `finally`. Этот сценарий не предназначен для удалённого
сервера. `tests/postgres_smoke.py` создаёт временную БД и пользователя с SELECT-only
правами внутри локальной PostgreSQL, затем удаляет их. Production-таблицы он
не использует. Оба сценария требуют предварительно запущенного Compose DEMO.

Во время проверки PostgreSQL обнаружена и исправлена ошибка распознавания
многострочного `SELECT`; добавлен regression test. Это подтверждает пользу
проверки настоящих SQL-запросов отдельно от mock-ответов.

## Границы проверки

- Desktop проверен на Linux через Qt `offscreen`, включая реальные сигналы,
  фоновые запросы и отрисовку окон. Установщик Windows/macOS не создавался.
- Локально использован Python 3.13.5, в серверном Docker-образе — Python 3.12.14;
  PostgreSQL 17.11, Django 5.2.17, PyQt6 6.11.0.
- PostgreSQL тестовой схемы повторяет документированные поля карты. Это
  не заменяет сверку с реальной WMS, проверку индексов и планов запросов.
- Производственная TLS-инфраструктура, реальный сертификат WMS и нагрузочное
  тестирование не проверялись.
- Offline-тест проверяет ранее открытые данные; полная копия WMS не сохраняется.

## Windows EXE — 19 сентября 2026

- Общий набор: **94 теста** проходят на Linux.
- Desktop: **32 теста** проходят на Windows Server 2022 x64 / Python 3.12.
- [Windows-сборка](https://github.com/Zazzpi/Pulsar/actions/runs/35394799688)
  собрала `Pulsar.exe` из коммита `19dea2922c101f45a2c9a9de1b0cedec7d35ad7d`.
- Собранный EXE запущен отдельным процессом вне каталога исходников.
  Проверены окно входа, открытие локального DEMO и отрисовка сводки,
  SQLite, встроенный requests и CA-сертификаты для HTTPS.
- Проверка окон использовала Qt `offscreen`. Запуск на персональном ПК
  проверяющего и подключение к серверу заказчика не проверялись.
- Адрес сервера заказчика неизвестен; встроенный DEMO работает полностью
  локально, без Python, Docker и серверного процесса на компьютере продажника.
- Исправлено освобождение SQLite-файлов на Windows; добавлена проверка,
  что файл можно переименовать и удалить сразу после операций DEMO.
- EXE и SHA256 опубликованы в [релизе v0.2.0](https://github.com/Zazzpi/Pulsar/releases/tag/v0.2.0).
