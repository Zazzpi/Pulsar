# WMS adapters

`get_repository()` выбирает `mock` или `postgres` через `WMS_MODE`. Оба адаптера
имеют методы `clients`, `client`, `summary`, `detail`, `metric_snapshot`.
Проверку наличия клиента, авторизацию и Django cache выполняет API выше этого слоя.

Списки возвращают `results`, `page`, `page_size`, `has_next`. SQL получает на одну
строку больше размера страницы, без запроса общего количества. Размер страницы
ограничен 100, номер страницы — 1000. Поиск клиентов — по имени или ИНН; введённые
`%` и `_` трактуются буквально.

История фильтруется по `created_at` в UTC, диапазон `[date_from, date_to)`,
по умолчанию последние 90 дней, максимум 90 дней за запрос. Дата без времени
означает полночь UTC. `stock` — текущее состояние, даты к нему не применяются.
Сводка учитывает текущие активные заказы и приёмки независимо от даты создания.
Число отгрузок — документы `shipped`/`delivered` по `shipped_at` за 90 дней.
Приход/расход — исходные движения (`reversal_of_id IS NULL`), как в примере карты;
это валовой поток оригинальных операций, а не восстановленный нетто-остаток.
Начисления суммируются вместе с отрицательными сторно.

`metric_snapshot(client_id, day)` считает движения за конкретные UTC-сутки,
а остатки и активности фиксирует на момент вызова. Исторические остатки за
прошлые даты из текущего `stocks_stock` восстановить нельзя.

## Ограничения карты и допущения

- Нет достоверных полей связей позиций/сканов приёмок, позиций документов и
  истории статусов. Эта детализация в MVP не запрашивается.
- Не предполагается существование недокументированных `id` у движений,
  остатков, приёмок и отгрузок. Поэтому при одинаковых значениях всех полей
  сортировки и изменении WMS между запросами OFFSET-пагинация может повторить
  либо пропустить строку. Для строгого курсора нужна полная схема ключей.
- **ASSUMPTION:** «близкий срок» — `DEADLINE_WARNING_HOURS`, по умолчанию 24 часа;
  просроченные незавершённые заказы также требуют внимания.
- **ASSUMPTION:** активная интеграция без успешной синхронизации (`NULL`) требует
  внимания. Порог устаревания `INTEGRATION_STALE_HOURS=1` взят из карты.
- Активность: заказы `new/confirmed/picking/packed`, приёмки
  `draft/confirmed/in_receiving`. Сводка не даёт транзакционного снимка разных
  таблиц: записи могут меняться между SELECT-запросами.

Production использует отдельный alias `wms`, роль PostgreSQL только с SELECT,
TLS и `OPTIONS` с `default_transaction_read_only=on`, `statement_timeout` и
`connect_timeout`. Проверка SELECT в адаптере — дополнительная проверка;
граница доступа обеспечивается правами базы. К этому alias не применяются
миграции. Ошибки логируются без параметров SQL и текста исключения драйвера.
